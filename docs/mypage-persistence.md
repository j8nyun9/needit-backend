# 마이페이지 저장 및 복원

마이페이지는 `GET /api/account`로 현재 사용자의 정보를 조회합니다. 전체 공개 목록 100개를 필터링하지 않고 작성자, 공감, 관심 프로젝트, 담당 프로젝트를 각각 조회하므로 오래된 내 글도 표시됩니다. 사용자별 조회는 1,000건씩 반복 조회합니다.

- 내가 등록한 불편함: `problems.author_id`와 로그인 사용자 UUID를 비교합니다.
- 공감한 불편함: `empathies.voter_id`로 복원합니다.
- 관심 프로젝트: `project_favorites.user_id`로 복원합니다.
- 참여 프로젝트: 현재 구현에서는 `projects.owner_id`가 본인인 담당 프로젝트입니다.
- 최근 활동: 저장된 글, 공감, 관심 등록, 담당 프로젝트로 재구성합니다. 취소·삭제한 항목은 제거됩니다.
- 프로필: `PUT /api/account/profile`로 수정합니다. Supabase Auth의 `auth.users.raw_user_meta_data.needit_profile`에 이름, 자기소개, 학부, 학년, 학교를 저장합니다. 기존 메타데이터는 보존합니다. 이메일 및 계정 ID는 수정하지 않습니다.
- 마이페이지의 선택한 탭은 사용자별 sessionStorage에, 현재 주 메뉴는 브라우저 탭의 sessionStorage에 저장합니다. 새로고침 시 페이지와 선택한 탭을 복원합니다.

새로고침 도중 로그인·데이터 조회가 끝나기 전에는 로딩 상태를 표시합니다. 조회나 저장에 실패하면 오류를 표시하며 성공한 것으로 처리하지 않습니다. 프로필 수정 폼의 저장하지 않은 변경은 복원 대상이 아닙니다.

이 변경 자체에는 새 SQL이 필요 없습니다. 앞서 추가된 작성자/삭제 기능과 프로젝트 출시 기능의 SQL은 적용되어 있어야 합니다. 과거에 작성자 정보 없이 저장된 불편함은 작성자를 확인한 뒤 `problems.author_id`를 지정해야 합니다. 예전 화면에서만 수정하고 서버에 저장하지 않았던 프로필 값은 소급 복원할 수 없습니다.

적용하려면 프론트엔드와 백엔드를 모두 배포합니다. 서버의 Supabase 키에는 Auth Admin 및 DB 서비스 권한이 필요합니다. 현재 서비스가 학생 생성·로그인에 사용하는 서버 전용 키를 유지하면 됩니다.
